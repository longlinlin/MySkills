# C/C++ 时序与集成测试

本文是 `code2flowchart` 主技能的 IT/Timing 模式说明，不是独立技能。仅在用户请求集成、接口协作、时序、超时测试或测试结果复核时启用。默认代码转流程图不进入本模式；不要求先生成 DD，也不依赖已安装其他图形技能。

## 先读规则与源码

读取 [UT/IT 检查规则](code-test-checklists.md)，重点执行“集成边界”“事件与时间判据”“输出与状态”。从实际技能目录解析路径；该模式由 AI 执行，不存在 `--it` 或 `--timing` 转换器选项。

明确用户选中的入口与模块，读取函数体、头文件、真实调用点、构建配置，以及用户提供的相关需求或时序设计。已有流程图先核对版本和边号；不从文件名、注释或 `.analysis.json` 单独推定协作事实。

若只有单个孤立函数，先列缺失的组件实现、接口声明或时序需求。仍可提供标为草稿的测试设计，不声称真实集成关系或验收上限已确认。

## 设计步骤

1. 列出边界内真实组件、边界外 stub/mock、触发输入和输出；不能把全部组件 mock 后称作真实集成测试。
2. 依据代码列接口契约和事件链，确定观测点、关联 ID、任务/中断上下文。只有有依据的先后关系才成为顺序断言。
3. 按实际代码选择正常协作、参数边界、错误返回、重试/超时、取消、队列和资源恢复场景；不添加源码没有的行为。
4. 为时序用例记录时钟、单位、分辨率、阈值来源、容差，以及每个事件的预期次数与顺序。阈值未知时保持 TBD，不能自拟毫秒数。
5. 复用项目已有测试框架、fake clock、事件记录与构建方式。涉及真实外设或看门狗的结论标明所需 PIL/HIL 与安全操作条件，未经授权不操作硬件。
6. 关联当前图版本/边序列和用例 ID；图形只用于解释路径，不能代替真实接口和时序断言。

## 交付与复核

按用户请求输出 `<scope>.it.md` 或 `<scope>.timing.md`；需要跨代码/图/用例映射时再输出 `.test-traceability.md`。文件放在本次图或测试产物目录，不自动生成无关设计文档。

执行测试前确认工程、环境与选中用例可用。使用者要求执行且权限具备时运行现有测试命令，记录返回码、实际断言、结果数量和日志；编译或环境失败记 BLOCKED，不当作被测逻辑 FAIL。框架退出码为零但全部跳过，也不是全部通过。

只有实际执行后才写 `.test-result.md` 的实测部分，并区分 PASS/FAIL/NE/BLOCKED/SKIP。主机逻辑测试不冒充实机时序，UT 分支覆盖不冒充接口覆盖或时序设计覆盖。失败后按影响范围回归，缺少执行能力时明确只完成设计。
