# 流程图生成后自检

在 `code2flowchart` 生成或修改流程图后、交给用户前执行。自检不是只检查 XML 是否可读，也不等同于运行 C 程序。

## 输入与输出

- 输入：目标函数源码、最新 `.drawio`，以及本轮生成的 SVG/PNG 和可用的分析 JSON。
- 先读 [绘图约定](flowchart-conventions.md)。本文是 `code2flowchart` 的参考规则，不是独立技能；上一级是主技能根目录，脚本位于其 `scripts` 目录。
- 输出：与 `.drawio` 同目录、同 basename 的 `<basename>.self-check.md`。只报告实际执行的检查和证据。
- 找不到源码或无法渲染时继续完成其余检查，但相关阶段必须标为未完成，不能声称整体通过。

## 1. 核对源码

读取真实函数及影响其行为的宏配置，不依据图的外观猜测逻辑。

- 核对每个 `if/else`、循环、`switch` 的可见分支及共同后继；保留空分支、fallthrough 和无限循环的真实含义。
- 核对 `break/continue/goto/return` 和已知不返回调用的目标。提前返回不能继续进入后续执行语句。
- 连续赋值可以合框，但不得越过判断、循环、标签、独立调用和退出语句；顺序和重要调用不能丢失。
- 宏、回调、断言和外部调用未展开时明确列出范围限制。轻量解析得到的图不是编译器验证过的完整 CFG。
- 组合枚举的路径不等于实际可达路径，更不等于已经运行过的单元测试。

## 2. 严格结构与几何检查

将命令中的路径替换为真实路径，记录退出码与完整问题摘要：

```powershell
python <code2flowchart根目录>/scripts/validate.py <最新图.drawio> --strict
```

- 检查缺失节点、重复 ID、悬空边、节点几何、穿框、边交叉与长距离重线。非零退出码不得记为通过。
- 长距离返回通道分开，在 End 上方局部合流；可达 End 只保留一条从上方进入的向下箭头。
- 若源码是无退出的无限循环，不应为了满足外观规则而伪造通往 End 的边；报告 End 不可达。
- 合流锚点不可见，不画黑点或跨线桥。公共出口短线不重复写 `return`，不创建新的返回动作。
- 具有真实共同后继的短距离合流是允许的，不应误报为需要拆开的长距离重线。

## 3. 视觉识别：能力可用时必须执行

先确认是否有可查看图像的视觉能力。可用时不能只读 SVG/XML 源码就跳过视觉检查。

1. 优先使用已安装的 draw.io 原生导出；也可使用本轮 SVG 的浏览器渲染，或已安装的 Pillow 生成有效 PNG。没有依赖时不要静默安装，不要生成空白占位图。
2. 用图像查看工具实际查看本轮完整图。大图再查看循环回边、提前返回、分支合流和 End 区域的清晰局部图；只看局部图不能代替检查整体连通与裁切。
3. 逐项查看：节点重叠、文字截断、连接断开、越界裁切、穿框、交叉、非预期重线、标签遮挡、箭头方向、合流黑点。
4. 特别检查最终出口：所有返回在 End 上方合流，只有一条向下箭头进入 End；不得残留多个侧面箭头或连续两个 `return` 标签。
5. 每次修复后重新生成图、运行严格校验并重新渲染。旧图片不能证明新图通过；不能手工修好截图却留下错误的 `.drawio`。

视觉能力不可用，或经过合理尝试仍无法产生有效渲染图时，记为 `SKIPPED` 并解释原因。几何检查可以补充证据，但不能替代或冒充视觉识别。浏览器渲染 SVG 时应说明没有验证 draw.io 原生渲染。

## 4. 修复与停止条件

- 优先修复已确认的源码目标错误，再修复布局、标签和箭头。不要为了让图好看而删除业务步骤或改写输入 C 源码。
- 结构修复最多 3 轮，视觉修复最多 2 轮；达到上限仍有问题时保留最新结果并明确报告，不无限重试。
- 不确定宏、语法或业务语义时记录待确认项，不自行编造条件或调用关系。
- 自检不授权安装依赖、上传业务代码、修改仓库配置、Git 提交或推送。

## 5. 自检记录

使用简短中文报告，至少包含：

```markdown
# 流程图自检

- 源码与函数：实际路径、函数名、宏配置
- 图文件：实际 .drawio 路径
- 总结：PASS / PARTIAL / FAIL

| 阶段 | 结果 | 证据 |
| --- | --- | --- |
| 源码核对 | PASS / PARTIAL / FAIL | 核对的分支、循环与退出，未展开的宏 |
| 严格校验 | PASS / FAIL | 命令、退出码、错误和警告数量 |
| 视觉检查 | PASS / SKIPPED / FAIL | 实际查看的渲染图、工具、完整图与局部图 |

## 问题与修复
实际问题位置、对应节点/边、修复内容和复测结果；无已知问题则明确写出。

## 未验证范围
未执行的编译、运行、实板验证，以及原生渲染或宏展开限制。
```

只有源码核对、严格校验和实际视觉检查均完成且无已知缺陷时才给 `PASS`。已发现的语义或布局缺陷给 `FAIL`；缺少源码、视觉被跳过或解析范围不完整时给 `PARTIAL`，并把限制带到交付说明中。
